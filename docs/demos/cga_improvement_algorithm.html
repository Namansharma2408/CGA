current problem

What your feature.cpp computes now

Your 19 features are correct as the paper describes, but several are too coarse and two have known bugs.

Bug 1: col_counts = row_counts — you copy row counts into col counts for "symmetric graphs". This is wrong for directed graphs and produces gini_col == gini_row always. Pass the CSC indptr separately.

Bug 2: is_scale_free is a binary 0/1 feature. The decision tree cannot learn a continuous boundary from a boolean. Replace with the raw gini_row (already present) — the tree will pick its own threshold.

Bug 3 (train_models.py): x_density = np.random.uniform(0.001, 1.0) — you randomise the most important feature instead of measuring it from actual BFS traversals. This is the main reason your models have poor accuracy.

new features to add

6 new features with high discriminative power

F1

degree_variance — var(row_counts)

The paper uses Gini to measure skew, but Gini is robust to outliers. High-degree hubs (star nodes) that dominate BFS are better captured by variance. Helps Model 1 separate social networks from random graphs.

f[19] = row_std² = Σ(d_i - d̄)² / n
F2

frontier_growth_rate — ratio of current frontier to previous

The paper's x_decreasing (F13) is binary. The rate of growth tells Model 3 whether the GPU→CPU transfer is imminent: a BFS expanding fast (ratio > 2) will soon peak; one contracting fast (ratio < 0.5) is near the tail. This is the single highest-value new feature.

f[20] = log(x_nnz / max(x_nnz_prev, 1))
F3

bucket_load_ratio — estimated load imbalance of PM-BHash

The load-balanced variants (LB-*) pay a prefix-sum overhead that's only worth it when the imbalance is high. Your model currently uses degree_x as a proxy, but that's the average — the max-degree column drives actual imbalance.

f[21] = row_max / max(row_mean, 1)   (peak-to-mean ratio)
F4

hash_collision_pressure — expected hash table conflicts

PM-BHash's inner hash table performs poorly when bucket occupancy is high (load factor > 0.7 triggers linear probe chains). This feature predicts that pressure directly and helps Model 2 prefer PB-MSPA when hash tables would thrash.

f[22] = degree_x_m / n_buckets    (n_buckets = 4 × n_threads)
F5

spa_init_ratio — cost of O(n) SPA init vs useful work

LB-MSPA's main bottleneck is initialising the dense SPA array. This feature quantifies when that overhead dominates: when the ratio is large, PM-BHash wins despite higher per-element cost.

f[23] = n / max(masked_valid_nnz, 1)    (init cost per result)
F6

transfer_cost_estimate — relative cost of GPU↔CPU data transfer

The paper's one-copy heuristic is a binary: transfer or don't. Model 4 would benefit from a continuous estimate of whether the transfer cost is justified by computation savings.

f[24] = (x_nnz × 8 bytes) / peak_bandwidth_GBs    (microseconds)

Use the platform's measured bandwidth from a one-time calibration at startup.

improved training algorithm

Algorithm: Profiling-based label collection

1

For each training graph G:

Run a complete BFS from the highest-degree vertex. At each iteration, record the feature vector and run ALL kernels in random order (to avoid cache warm effects), recording their execution times.

2

Label assignment — do NOT use heuristic rules.

The optimal label for each row is argmin(kernel_times). The paper trains from ground-truth timing, not from "if xd > 0.05 then SpMV". Your current code does the latter, which just teaches the tree to reproduce your hardcoded threshold — not to learn better ones.

y_cpu[i] = argmin_k { t_PM-BHash, t_LB-PM-BHash, t_PB-MSPA, t_LB-PB-MSPA, t_LB-MSPA }
3

Sample weighting — Eq. 6 from paper (you have this, use it properly):

Your Python code has sample_weights_eq6 but train_models.py never calls it. Pass the timing matrix to the weight function and use the weights in clf.fit(X, y, sample_weight=w).

w_i = exp( β/(k−1) × Σ_{j≠opt} (t_j / t_opt − 1) )

This gives high weight to cases where the optimal kernel is clearly better, and low weight to cases where all kernels are similar. β=1.0 is a good start.

4

Stratified training split by graph family:

Currently no stratification. If 80% of graphs are scale-free, the model overfits to that family. Use StratifiedKFold with graph family as the strata, not random split. 

from sklearn.model_selection import StratifiedKFold
skf = StratifiedKFold(n_splits=5, shuffle=True)
for train_idx, val_idx in skf.split(X, graph_family_labels):
    # train on fold, evaluate on held-out fold
    ...
5

Depth-of-iteration weighting:

Early BFS iterations (depth 1-3) are rarer but more important — they determine platform choice. Late iterations (depth N-3 to N) are also critical for the GPU→CPU transfer. Give middle iterations lower weight.

depth_weight[d] = 1 + 2×exp(−d/3) + 2×exp(−(D−d)/3)

Multiply depth_weight[d] into the sample weight w_i from Eq.6.

6

Depth for Model 1 (Platform Selector): don't use depth=6 for all models.

Model 1 only uses matrix features (9 dims) and classifies 2 classes. It needs depth ≤ 3 or it will overfit to training graph indices. Models 2-4 use all 25 features and classify 5-7 classes — they can use depth 6-8.

M1: max_depth=3  | M2: max_depth=7  | M3: max_depth=6  | M4: max_depth=8

Platform-adaptive re-training

The paper trains once and deploys. Your novel extension: train a "base model" on a reference platform, then when deployed on a new platform, collect 50-100 BFS timing samples and fine-tune by re-fitting only the leaf values of the existing tree (not the structure). This is faster than full retraining and preserves the tree structure.

current problem in your DTA

3 issues in your inference.cpp DTA

Issue 1: UCB uses ema_ms for the score but the bonus term is based on n_obs. After 20 iterations, the bonus shrinks to near zero even for rarely-tried kernels. Use a sliding window count of recent observations instead of total count.

Issue 2: Threshold gradient is only updated when the chosen kernel matches a specific category (SpMV, PM-BHash). After a few iterations, once greedy selection locks in, thresholds stop updating entirely. Add a forced gradient update even when the rival's EMA is not fresh enough.

Issue 3: explore_left only decrements when a non-greedy choice is found. If the UCB score always agrees with greedy (e.g. all kernels have been tried), exploration never fires. Add a random probe every 10 iterations as a fallback.

improved DTA algorithm

Revised algorithm: Sliding-window UCB + Forced Exploration

A

Replace total-count UCB with sliding-window UCB (SW-UCB):

Standard UCB1 gives diminishing bonuses over time. SW-UCB uses a sliding window of the last W observations per kernel, so a kernel not tried in W iterations gets a fresh exploration bonus.

UCB(k, t) = EMA_k − c × √(ln(min(t, W)) / n_obs_in_window(k))

Set W = max(10, 2 × n_kernels). If a kernel has 0 observations in the window → return −∞ (force try).

B

Counterfactual gradient — update thresholds even without fresh rival data:

When you choose PM-BHash but PB-MSPA has no observations yet, your current code skips the m_density threshold update. Instead, use a prior: assume the rival's time equals the global median EMA as a conservative estimate. 

double rival_ema = best_rival_ema(rivals);
if (rival_ema < 0) {
    // No observations — use global median as conservative prior
    rival_ema = global_median_ema();
}
t_m.update((rival_ema / max(time_ms, 1e-9) - 1.0) * feat[12]);
C

Periodic forced probe (ε-greedy fallback):

Every 10 iterations, force-try the kernel with the oldest last-use timestamp. This prevents the system from converging prematurely on a suboptimal kernel when hardware state changes. 

if (iteration % 10 == 0) {
    std::string oldest = min_element(stats,
        [](auto& a, auto& b){
            return a.second.last_used_iter < b.second.last_used_iter;
        })->first;
    return oldest;  // forced probe, overrides greedy
}
D

Momentum decay — reduce oscillation near the optimum:

Your threshold momentum is fixed at 0.9. Near the optimum, this causes sustained oscillation. Use a dampened momentum that reduces as the gradient magnitude shrinks.

β(t) = 0.9 × exp(−|gradient| × 0.1)    (range: [0.3, 0.9])
E

Separate learning rates per threshold type:

Currently all three thresholds use the same lr * 0.99 decay. The x_density threshold should decay slowly (it governs a large fraction of decisions). The LB threshold should decay fast (very few BFS iterations hit the LB boundary). Differentiate:

t_x: lr₀ = 0.05, decay = 0.995  (slow — high impact)
t_m: lr₀ = 0.03, decay = 0.99  (medium)
t_lb: lr₀ = 0.01, decay = 0.98  (fast — rare event)
F

New threshold: intra-iteration variance (F1 from features):

Add a 4th adaptive threshold t_var on degree_variance (feature F1) to decide between LB and non-LB variants. This replaces the current degree_x > t_lb rule which conflates two distinct signals: average load vs peak load.

if degree_variance > t_var → prefer LB variant
if degree_x > t_x → prefer SpMV/SpMSpV boundary
architecture improvement

Replace single tree with cost-sensitive ensemble (Model 2)

Model 2 (CPU kernel selector) has 5 output classes and the performance difference between classes varies by 10-100×. A single tree misclassifies equally-weighted. Use a cost-sensitive random forest where misclassifying PM-BHash as LB-MSPA (10× slower at high sparsity) costs more than misclassifying LB-MSPA as PB-MSPA (1.2× slower).

1

Build a cost matrix from profiling data: cost[i][j] = average slowdown when true class is i but you predict j.

cost[PM-BHash → LB-MSPA] ≈ 8×
cost[LB-MSPA → PM-BHash] ≈ 1.3×
cost[PB-MSPA → PM-BHash] ≈ 2×
2

Incorporate cost matrix into sample weights: w_i = cost[true_class, second_best_class] instead of Eq.6 alone. This makes the tree avoid costly misclassifications even when accuracy is similar. 

w_combined[i] = w_eq6[i] × cost_matrix[y_true[i], y_second_best[i]]
3

Use a 3-tree ensemble for Model 2 only (the highest-variance model): train one tree on scale-free graphs, one on mesh, one on unknown. At inference, pick the tree based on Model 1's platform prediction.

This is faster than a full random forest and interpretable — you can still export the 3 trees to C++ without sklearn at runtime.

new: Model 0 — fast pre-filter

Add a depth-0 decision before Model 1

For the very first BFS iteration (depth=1, frontier size=1), no ML model is needed — the optimal kernel is always PM-BHash (single vertex). For the last iteration (frontier size=1), also PM-BHash. Short-circuit these cases before running any model. 

// In InferenceEngine::select_kernel():
if (x_nnz == 1) return {"CPU", "PM-BHash"};  // first/last iteration
if (x_nnz > n * 0.3f) return {"GPU", "SpMV"}; // dense frontier
// ...then proceed to Model 1

This eliminates model inference overhead for a significant fraction of iterations (depth-1 and depth-final are universal) and is provably optimal.

new: confidence-gated DTA

Only update DTA thresholds when the model is confident

Your static model outputs a hard classification. Add softmax-style confidence estimation: if the two top candidate classes have close timing estimates (within 15%), do not update the threshold — the update signal is noisy. Only update when the winner is clearly faster.

if (rival_ema / time_ms - 1.0) < 0.15 → skip gradient update
if (rival_ema / time_ms - 1.0) > 1.5 → large update step (×2.0 lr)
current issue

One-Copy Execution Flow: your implementation is incomplete

In your InferenceEngine::select_kernel(), the STATIC mode correctly implements Model 4's GPU→CPU dispatch. But in DTA_MODE, you bypass Models 1-4 entirely and only use the DTA. This means DTA never benefits from the one-copy transfer optimisation — it always stays on the same device it started on.

Fix: run DTA for kernel selection within each device, but use the static Model 1 for initial platform selection, and check the Model 4 condition (x_decreasing) in DTA mode too. 

// Fixed DTA mode:
if (mode == DTA_MODE && dta) {
    if (iteration == 0) {
        // Use Model 1 for initial platform — DTA has no data yet
        platform = m1->predict_name(feat);
    }
    std::string k = dta->select_kernel(feat);
    // Check one-copy trigger condition (paper Fig. 9)
    if (on_gpu && feat[13] > 0.5f) {  // x_decreasing
        std::string k4 = m4->predict_name(feat);
        if (k4 != "SpMV" && k4 != "Sort-Based SpMSpV") {
            trigger_one_copy_transfer();
            return {"CPU", k};
        }
    }
    return {k == "SpMV" ? "GPU" : "CPU", k};
}
performance improvement

Concurrent model predictions — reduce inference overhead

The paper (Section IV-D) explicitly states: "Model 2, 3 and Model 4 make predictions concurrently". Your current code runs them sequentially. Parallelize with std::async: 

auto f2 = std::async(std::launch::async,
    [&]{ return m2->predict_name(feat); });
auto f4 = std::async(std::launch::async,
    [&]{ return m4->predict_name(feat); });

// While those run, do Model 1 on main thread (cheapest — matrix features only)
std::string plat = m1->predict_name(feat);

// Now wait for results
std::string cpu_k = f2.get();
std::string uni_k = f4.get();

On a 4-core CPU, this reduces inference from ~3× tree traversals sequential to ~1× parallel, saving 0.01-0.05ms per iteration — meaningful when PM-BHash itself takes 0.1ms.

performance improvement

Feature caching — avoid recomputing stable features

Matrix features (f[0]-f[8]) and several hybrid features are constant within a BFS run. You already compute them once, but build_feature_vector() recomputes log1p(n), log1p(nnz), etc. on every call. Cache the first 9 values: 

// Compute once and store in InferenceEngine:
static_part[0..8] = build_static_features(ms);

// Each iteration: copy and fill dynamic part only
FeatureVector feat;
std::copy(static_part, static_part+9, feat.v);
build_dynamic_features(feat, x_nnz, m_nnz, x_nnz_prev);

The new features F1-F3 (degree_var, growth_rate, peak_to_mean) are also static — compute once per graph.
